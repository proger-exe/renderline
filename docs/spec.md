# Video Script Engine (Telegram MVP v1.1)

## 1. Назначение
MVP предназначен для автоматической сборки вертикальных видео (TikTok / Shorts) из загруженных ассетов на основе сценария, собранного через Telegram‑бота с точностью таймингов до секунды.

Ключевая идея: **пользователь не монтирует видео — он описывает его структуру**, а система рендерит результат автоматически.

---

## 2. Основные Kill‑Features

1. **Timeline‑сценарий через Telegram**  
   Сценарий собирается как последовательность сегментов: `ассет + IN + OUT`.

2. **Точность до секунды**  
   Все тайминги вводятся и хранятся в секундах, без таймкодов и фреймов.

3. **Красивые субтитры (manual track)**  
   Пользователь добавляет строки субтитров с таймингами. Рендер в стиле TikTok: жирный шрифт, обводка, тень, безопасная позиция. Реализация через ASS/SSA (libass).

4. **SFX и фоновая музыка по таймкоду**  
   Вставки саунд‑эффектов в конкретный момент итогового ролика + опциональная фоновая музыка с регулировкой громкости.

5. **Timeline‑preview (сетка времени)**  
   Во время монтажа бот показывает визуализацию таймлайна в виде линий на временной шкале (ASCII/Unicode), чтобы сразу видеть структуру ролика.

6. **Полная автоматизация рендера**  
   Пользователь нажимает одну кнопку «Рендер» и получает готовый mp4.

7. **Preset TikTok (9:16)**  
   Видео автоматически приводится к вертикальному формату, без ручных настроек.

8. **Batch‑вариации (MVP‑light)**  
   Возможность сгенерировать несколько версий одного сценария со случайным сдвигом таймингов ±1–2 сек.

---

## 3. Пользовательский поток (User Flow)

1. Пользователь запускает бота
2. Создаёт новый проект
3. Загружает видео‑ассеты
4. Собирает таймлайн из сегментов
5. Добавляет субтитры (опционально)
6. Добавляет BGM / SFX (опционально)
7. Просматривает таймлайн‑сетку
8. Выбирает пресет (TikTok)
9. Запускает рендер
10. Получает готовое видео

---

## 4. Интерфейс Telegram‑бота

### 4.1 Главное меню
- ➕ Новый проект
- 📁 Ассеты
- 🎬 Таймлайн
- 📝 Субтитры
- 🔊 Аудио (BGM / SFX)
- 📊 Таймлайн (просмотр)
- ⚙️ Пресет
- 🚀 Рендер

---

### 4.2 Проект
**Project** — логическая единица одного видео.

Поля:
- id
- owner_id (telegram_id)
- title
- preset
- status
- created_at

---

### 4.3 Ассеты
Пользователь загружает видеофайлы в проект.

Каждому ассету присваивается короткий алиас:
- A, B, C…

Отображение:
- Имя
- Алиас
- Длительность (в секундах)

---

### 4.4 Таймлайн
Таймлайн — упорядоченный список сегментов.

**Segment**:
- asset_alias
- in_sec
- out_sec
- order

Пример отображения:
1) A 0→10
2) B 10→15
3) A 15→22

Кнопки:
- ➕ Добавить сегмент
- ✏️ Редактировать сегмент
- ↕️ Переместить
- 🗑 Удалить
- 📊 Просмотр (сетка времени)

---

### 4.5 Таймлайн‑preview (сетка времени)

Пример отображения (1 символ = 1 сек):
```
0         5        10        15        20
|----|----|----|----|----|----|----|
A: [##########..............]
B: [..........#####.........]
A: [...............#######..]
```

Опционально:
- 🔍 x0.5 (1 символ = 2 сек)
- 🔎 x1 (1 символ = 1 сек)

---

### 4.6 Субтитры

**Subtitle**:
- start_sec
- end_sec
- text

Пример:
- 0–2: «ты охуеешь»
- 2–6: «но это реально работает»

Добавление:
1. Выбор start (инкременты −5 / −1 / +1 / +5)
2. Выбор end
3. Ввод текста

Валидация:
- end > start
- end ≤ длина итогового ролика

---

### 4.7 Аудио (BGM / SFX)

**BGM**:
- файл
- volume (0.0–1.0)

**SFX**:
- файл
- at_sec
- volume

---

## 5. Внутренний формат сценария (Execution‑Plan)

```json
{
  "preset": "tiktok",
  "assets": {
    "A": {"path": "assets/first.mp4"},
    "B": {"path": "assets/second.mp4"}
  },
  "timeline": [
    {"asset": "A", "in": 0, "out": 10},
    {"asset": "B", "in": 0, "out": 5},
    {"asset": "A", "in": 10, "out": 15}
  ],
  "subtitles": [
    {"start": 0, "end": 2, "text": "ты охуеешь"},
    {"start": 2, "end": 6, "text": "но это реально работает"}
  ],
  "subtitle_style": "tiktok_bold_v1",
  "audio": {
    "bgm": {"file": "trend.mp3", "volume": 0.25},
    "sfx": [
      {"at": 1.2, "file": "whoosh.wav", "volume": 0.6},
      {"at": 6.0, "file": "hit.wav", "volume": 0.8}
    ]
  }
}
```

Execution‑plan является источником истины для рендера.

---

## 6. Архитектура MVP

1. **Telegram‑бот** (aiogram 3)
   - FSM состояний
   - управление проектами, ассетами, таймлайном

2. **API** (FastAPI)
   - CRUD для проектов
   - запуск задач рендера

3. **Очередь задач**
   - RabbitMQ

4. **Worker (Render Engine)**
   - Python + FFmpeg
   - сборка видео, аудио, субтитров

5. **Хранилище**
   - локально / MinIO / S3

6. **База данных**
   - PostgreSQL

---

## 7. Алгоритм рендера

1. Загрузка execution‑plan
2. Вырезка сегментов (`ffmpeg -ss -to`)
3. Приведение клипов к 9:16 и единому FPS
4. Склейка видео
5. Аудио‑микс:
   - оригинальный звук
   - BGM
   - SFX по таймкодам
6. Генерация ASS‑субтитров
7. Финальный рендер mp4

---

## 8. Ограничения MVP (осознанно)

- Нет GUI
- Нет автосубтитров из речи (ASR)
- Нет автопостинга
- Нет ролей и мульти‑юзеров
- Нет авто‑подбора музыки и эффектов

---

## 9. Критерии успешности MVP

MVP успешен, если:
- сценарий полностью собирается через Telegram
- таймлайн и сабы редактируются без боли
- рендер запускается одной кнопкой
- результат не требует ручной доработки
- можно стабильно генерировать десятки роликов
